# Cloudsneeker Knowledge Base

This knowledge base is the internal map of the Cloudsneeker repository. It explains what the product is, how the pieces fit together, and where to change them. Public user documentation is the Mintlify site in [`cloudsneeker/docs/`](../cloudsneeker/docs/) (guides are hand-written; check and framework pages are generated by `cloudsneeker/tools/gen_check_docs.py`). The upstream [`docs/`](../docs/) tree is kept for merges and is not published.

Read these pages in order when you are new to the repository:

1. [Product and Naming](product-and-naming.md) — what Cloudsneeker is, and which names stay in code
2. [Architecture](architecture.md) — runtime services, data stores, and request paths
3. [Scan Lifecycle](scan-lifecycle.md) — how a provider scan becomes findings
4. [Components](components.md) — SDK, API, UI, MCP server, and dashboard
5. [Local Development](local-development.md) — setup, commands, and conventions
6. [Coding Standards](coding-standards.md) — Prowler style, structure, and which skill to open
7. [Feature Verification](feature-verification.md) — unit tests, compatibility, and integration checks
8. [Upstream Sync](upstream-sync.md) — how to add features and still merge Prowler
9. [Upstream Hooks](upstream-hooks.md) — every Prowler file Cloudsneeker touches, the brand modules, and the build-time rebrand rules

Agent rules for day-to-day coding stay in the root [`AGENTS.md`](../AGENTS.md) and in each component `AGENTS.md`. Cursor rules in [`.cursor/rules/`](../.cursor/rules/) enforce the upstream split on every session. Skills under [`skills/`](../skills/) hold the patterns those rules point to. Use this knowledge base for orientation, then open the matching skill before changing code.
