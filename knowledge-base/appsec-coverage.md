Not offered:

* Virtual machine image (`vm`): The engine (experimental) reads a local VMDK file or an AWS AMI or EBS snapshot. Disk images are too large for the upload path and the AWS form needs a per-tenant role with EBS direct API access; neither is built.
* Configuration-only scan (`config`): Covered by the misconfiguration scanner on repository, filesystem and Infrastructure as Code targets.

## Feature Coverage

### Targets

| Capability | Status | Detail |
| --- | --- | --- |
| Container image | Partially Implemented | Single images and image lists run on the new engine. A source that is a whole registry still uses the registry scan and gets findings but no component inventory or lifecycle. |
| Code repository | Implemented | HTTPS with token (branch, tag, commit) and SSH (cloned, then scanned as a directory). |
| Local filesystem | Implemented | Uploaded ZIP or TAR archive, extracted with path and size checks. |
| Root filesystem | Implemented | Uploaded archive scanned with installed-package detection. |
| Virtual machine image | Missing | The engine (experimental) reads a local VMDK file or an AWS AMI or EBS snapshot. Disk images are too large for the upload path and the AWS form needs a per-tenant role with EBS direct API access; neither is built. |
| Kubernetes cluster | Implemented | Cluster report parsed per resource; namespace and kind filters; node collector off by default. Experimental in the engine. |
| SBOM document | Implemented | CycloneDX JSON and SPDX (JSON, tag-value). |
| Infrastructure as Code repository | Implemented | Repository scan with the misconfiguration scanner on by default. |

### Vulnerabilities

| Capability | Status | Detail |
| --- | --- | --- |
| OS and language package vulnerabilities | Implemented | Class, type, package, installed and fixed version, status, PURL, layer, data source, vendor ids, CWE, references, published and modified dates. |
| CVSS | Implemented | All vendor vectors and scores stored. The finding's score is the base score from the vendor that set the severity (newest CVSS version), else NVD, else the highest reported. |
| Direct and transitive classification | Implemented | From the package relationship in the report; unknown when the ecosystem does not provide it. |
| EPSS and known-exploited data | Unsupported | The engine reports neither. The finding has nullable fields and the score counts them only when set; no feed is connected. |
| Separate metrics (instances, unique CVEs, affected packages, fixable) | Implemented | Computed by the findings summary endpoint; never one mixed number. |
| Kubernetes core component vulnerabilities | Partially Implemented | Reported when the cluster scan returns them; no separate KBOM view. |

### Product

| Capability | Status | Detail |
| --- | --- | --- |
| Application and asset inventory | Implemented | Applications group targets and carry criticality, environment, exposure and a default profile. Branch and commit are recorded per scan, not modelled as inventory levels. |
| Scan profiles | Implemented | Six built-in profiles; custom profiles with create, clone, edit, disable and delete; assignment per target, application and target type. |
| Finding deduplication and lifecycle | Implemented | One row per fingerprint and target; new, open, fixed and reopened states with history. A finding is fixed only when a complete scan that covers it stops reporting it. |
| Finding correlation across assets | Partially Implemented | A finding lists the same advisory or rule on other assets and other issues in the same package. There is no merged cross-asset record. |
| Risk prioritization | Implemented | Explainable score from severity, CVSS, fix availability, dependency directness, application context and age; thresholds are tenant settings. |
| Remediation deadlines | Partially Implemented | A deadline per severity from first detection, overdue filter and counts. Ownership is the application owner and the triage assignee; there are no overdue notifications. |
| Dependency tree view | Missing | Dependency edges are stored and exported; the UI lists direct and transitive packages but draws no tree. |
| Outdated package detection | Unsupported | The engine reports fixed versions for vulnerable packages only; it has no latest-version data. |
| Git metadata | Partially Implemented | Repository URL, branch, commit, author and tags are stored on the scan for HTTPS repositories. SSH repositories are scanned as a directory and have none. |
| Assistant integration (finding explanation) | Missing | The assistant has no tools for the new findings, components or applications yet. |
| Verification against a live engine | Missing | Parser and command tests use fixtures built from the engine's types at the pinned version. No scan has been run against the real binary in this change. |
