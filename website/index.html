How it works

From first connection to fewer risks.

Five steps, one workflow. Pick a step to see what it looks like.

Cloud accounts connect with read-only access. Add repositories, images and clusters for application scans.

Scan profiles choose which checks and frameworks apply. Run scans on demand or on a schedule.

Filter by severity, framework and resource, follow Attack Paths, and ask Seeker AI what to fix first.

Send findings to Jira or Slack, alert by email, and track progress until the next scan confirms the fix.

Security

Built to be trusted with your cloud.

A security platform has to earn trust. These controls are in place today, and our security page lists what is still on the roadmap.

How we protect your data

Read-only cloud access

On AWS, an IAM role you create based on the SecurityAudit and ViewOnlyAccess managed policies, assumed with an external ID. Revoke it at any time.

Encrypted credentials

Cloud credentials and secrets are encrypted by the application before they are stored.

Tenant isolation

Row-level security in the database keeps each customer's data separate.

Roles and single sign-on

Role-based access decides who can view findings, run scans or manage settings. SAML SSO is supported.

No changes without you

Governance policies run as dry runs and do not modify your resources.

Deploy in your account

Run the platform inside your own AWS account so scan data stays with you. On request.
